# 沙箱验证服务端真实产物，而非等价实现

沙箱（Lima VM）原本用 TS 装配器生成的 config 驱动内核，验证的是那套实现的语义而非生产链路。改为在 VM 内启动 `sb-sync server`、取回它实际响应的配置再驱动内核。沙箱的价值是隔离网络下的分流与阻断裁决测试，因此节点用假 URI：被测对象是内核的裁决结果，不是代理连通性

## Consequences

- 沙箱的通过与否直接对应可供 SFM 消费的那份配置，闭环成立
- 需要 VM 内可执行的 Linux 二进制，测试链路新增「先构建再验证」的前置
- 底模的 `rule_set` 是远程引用，沙箱内要么真联网拉取，要么改写为本地路径指向编译产物
- 内核 debug 日志是路由裁决的观测面，而底模顶层无 `log` 键，日志级别须由沙箱专用配置的 `overlay` 注入
